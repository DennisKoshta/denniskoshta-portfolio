H-1: line 686 (347's table, Bell eats counter)

Signal.

  • On 686's own orbit the margin reached k_align/(M-1) = 0.9755 at phase 1572 (M = 13,204, k_align = 12,879).
  • 347's own orbit never went above 0.467 (to phase 16,800), and 441's stayed at or below 0.42.
  • The fast map has run 686 to phase 15,304 (M = 153,097, about 2e14 steps) without a halt.
  • The only other phase above 0.5 is phase 725 (0.73).
  • In this table halting comes only from margin breaks. From 347's notes: 3 halts in 380 phases with M-1 < k_align, and 7 in 3,293 with M forced below k_align.

Model route.

  1. Resume reports/halting-hunt/margins/scripts/t347fam.py, which drives the fast map in machines/1RB1RF_1RC0RA_1LD1RE_1LE0LE_0RA0LD_0RB---/scripts/deepen3_fast.py, from phase 15,304 on 686's start. reports/halting-hunt/parked/l347_resume.py shows how to resume from a full-counter dump.
  2. Log every phase with a ratio above 0.9.
  3. Whenever the ratio reaches 1 or more, save that phase start and run that one phase by direct simulation (tools/sim C core: about 2M² steps, roughly 1 to 3 minutes at M ≈ 1e5).
  4. Cost: about 0.3 s per phase at M ≈ 1.6e5 (347's extension). The cost per phase grows with M, so 5e4 phases take about 6 h and 1e5 phases about a day.
  5. Cheaper extension: derive a J-rule-level phase map from 347's rule table (J-rule, aligned walk, k_align as a sum of carries over chain heads). It runs in O(digits) per phase instead of O(M).

Certification if it halts.

  • First choice: RWLAcc62_BigUint solve_halt' with raised budgets (the RWLAccHaltv6.v route). The bell (10)^M and the counter blocks are run-length friendly.
  • Fallback: a W5-5-style chunk replay of the phase model (machines/1RB0RE_1RC0RA_0LD0RB_1LA0LE_1LC1LF_0LC---/*.v).

Risks.

  • 347's tests show that mild breaks do not halt: 0 of 1,100 with M in [3k/4, k]. 6 of the 7 forced halts had M < k_align/3, so a halt needs a severe break.
  • The 0.9755 spike may be a one-off: only 2 of 15,000 phases went above 0.5.
  • 686 is not ours. It falls under our 'Bell eats counter' class claim, but it still needs its own claims line.

H-2: line 244, with 216 and 701 (Counter Class 3, CounterClass3v1 halter tables)

Signal.

  • 244 is 1 transition from both CounterClass3v1 halting tables (the TM4 table, and the TM5/TM6 table, which are one table from two starts). 216 and 701 are 1 transition from the TM4 table. Checked here.
  • Per the hints scout, the differing transition fires only during startup: 4 to 6 times, all before step 787,288. After that each machine runs a halter's table from its own configuration.
  • The upstream accelerator (astep/skip_lr, P0_n) checks out empirically on our tables.
  • The Python port reproduces TM4's own halt at 1.016e7 msteps.
  • Ours run to 5.9e8 to 6.9e8 msteps without halting.
  • Halting needs a consumption wave to leave the last tail block at 1. TM4 halted with tail [..,118,16,1]. Our tails cycle through [..,23,12], [..,74,11] (244) and [..,40,14,5] (216/701).

Model route.

  1. Reuse reports/halting-hunt/hints/cc3acc.py and cc3trace.py.
  2. Derive one consumption wave as one macro step: the tail-rebuild map.
  3. Validate it wave by wave against cc3acc.py for every wave up to 6.9e8 msteps.
  4. Run all three machines in one driver and log the tail at every wave.
  5. Keep a guard that the differing transition never fires again after startup. If it does, the model is no longer our machine.

Certification if it halts.

  • Copy the CounterClass3v1 module (P0_n, astep_spec, msteps_halt) with our TM string, a startup init and a larger msteps budget.
  • This works while the halt is within roughly 1e9 msteps of vm_compute. Beyond that, the wave step needs its own Rocq lemma.

Risks.

  • Already 70x past TM4's halting point, and the tails are not trending toward 1.
  • reports/targeting.md marks Counter Class 3 as taken. Upstream's CounterClass3v2.v (10-07, "M1") is a macro-inductive nonhalting proof. Its machine is 7 transitions from ours and is not on the 740 list, but someone may be preparing nonhalting proofs for these three.
  • Upstream had this accelerator (with an msteps budget of 10^10) and did not certify these three. Either they were never tried or they did not halt within that budget.
  • These three are kept despite the "taken" note for three reasons: the brief's exclusion list does not name Counter Class 3, the upstream work there is on the nonhalting side, and the signal is exceptional.

H-3: line 269, with 43 (R5, SO structural counter, ours STUCK)

Signal.

  • The first counter overflow, at 4.391e15, did not halt. It reset the machine to an almost blank new epoch.
  • Halting is decided at overflows. The halting path there is 0 <A 101, which halts in 4 steps (machines/1RB1LA_1RC1RE_1RD0RD_1LA1RC_1RF0LE_1RA---/work/r5_followup.md).
  • 43 is the same table from D, mirrored (checked here).

Model route.

  1. The seeded qsim (reports/halting-hunt/parked/r5/r5q.py, from work/r5_post_ckpt.bin) matches direct simulation on the full 1.0066e8-cell tape.
  2. Its 4 h run (r5q_long.jsonl) is at 4.615e15 steps (loop 62M) with 0 prover rules, so it only does chain moves and cannot reach the next overflow.
  3. Derive an epoch model: the counter's per-cycle consumption, the reservoir size and the overflow trigger. Fit it on epoch 1 (blank to 4.391e15) and on the start of epoch 2.
  4. Validate it against the r5q dumps and scripts/r5run (direct C).
  5. Fast-forward to the next overflow and apply the overflow rule, then repeat. Run 43 on the same model.

Certification if it halts. No template reaches that depth. It would need an epoch-level certified replay (in the style of C2-552's Sk1Auto certificate runner) or solve_halt', if run-length acceleration happens to suffice.

Risks.

  • The next overflow is probably exponentially later than the first.
  • If the epochs are self-similar, R5 is probably nonhalting.
  • r5_followup.md lists the epoch-map stage as Dennis's call. Today's hunt approval covers exact models, but this should be stated when it is launched.

H-4: line 362, with 433 (Chaotic Bell Class 2)

Signal.

  • The k=4 qsim run reached 10^145.8 steps in 180 s.
  • It found 1,885 Collatz rules, each used once (one fresh epoch per rule). The log-steps gain per time doubling held at about 39, so the run is keeping up.
  • 433 is the same table from C (checked here). Its run reached 10^135.7.
  • RWLAccHaltv6.v certifies a halt of this table from 362's start B, so the halting branch is reachable from these dynamics.

Model route.

  1. Run tools/qsim.py (.venv/bin/python -B, k=4, backsymbol + prover + recursive) as in the deep scout's worker.py: 1 to 2 h per start, with progress lines, nice -n 10 and ulimit -v 6000000.
  2. Add a k=2 run as a cross-check.
  3. On a HALT, re-derive the halt with an independent run-length simulator before any proof work.

Certification if it halts. RWLAcc62_BigUint solve_halt', the generic certified run-length executor already used on this exact table.

Risks.

  • A lottery with no trend to watch.
  • Upstream's RWLAcc sweep has probably already run these starts to some budget.
  • qsim's prover rules reach further than run-length shifts. A halt at about 10^300 steps may therefore be out of solve_halt''s reach, and there is no template for replaying qsim's rules in Rocq.
  • qsim can blow its memory limit (518's k=2 run died at the cap).
