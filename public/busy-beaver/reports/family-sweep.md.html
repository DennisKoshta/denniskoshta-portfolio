Family sweep: untouched holdouts related to our kills

2026-10-10. Inputs: data/holdouts/2026-10-07_778.txt (778 entries), data/holdouts/2026-10-07_eqv_1590.txt (778 groups, 1,590 machines), the 9 machines/*/status.json with KILLED_NONHALT (#2, #3, #4, #11, #12, #12-twin, #24, #25, #33), their proof.md/check_proof.py, reports/forensics/remaining_778.tsv (sheet fields), data/discord/, reports/landscape.md §7 (claims), data/solved_index.tsv.

Simulation and table matching are evidence, not proof. Only a tools/check_kill.sh PASS counts.

Bottom line

  • Three new same-table relatives. Each is an untouched holdout that runs a killed machine's own transition table (up to renaming states) from a different start state. On each one, simulation shows the run entering the parent's proven invariant. If that holds, the parent's rules and invariant carry over as they are, and only the init changes, as with #24, #25 and #33. 1. line 388 1RB0LD_1RC0RE_1LD0RE_1LA0LA_1RB1RF_1RB---: kill #33's table renamed (no mirror), started in #33's D. Equivalently, #11's table mirrored and started in #11's C. 2. line 604 1RB0RD_1RC1RF_1LD0LE_1RA0LC_1RE1LC_0RA---: kill #3's table renamed (no mirror), started in #3's B. This is the 4th holdout with that table (A = #3, B = this, C = #25, D = #24). It is not mentioned anywhere in the project yet. 3. line 17 1RB---_0LC1RF_1LE0RD_0RB1RC_1RD0LE_0RC1RA: kill #4's table renamed (no mirror), started in #4's F. Not mentioned in any machine notes yet.
  • Excluded as claimed: line 541 1RB0RB_1LC0RA_1LE0LD_1LC1LF_1RA0LD_1LC--- (#11's table from B; Level 1 tab, "Done By: hipparcos", Discord thread). It would be as cheap as 388 if the duplicate-work question is resolved.
  • Relation (2), 1–2 transitions after the best renaming + mirror: no untouched holdout. The only holdouts at distance 1 are already touched: #32 and R4 (from #11/#33), 1RB0RA_1LC0RE_0LC0LD_1RD1LB_0RF1RA_0RB--- (from #2) and the #12 twin pair. Nothing is at distance 2. At distance 3–4 there are 16 untouched representatives, but every one first uses a differing transition within 31 steps, and most are in another sheet class (full table below).
  • Relation (3), trajectories: the only exact twin of a kill that is untouched is 388, twin of #11 (77,691 / 77,685 cells and 38,839 / 38,836 nonzeros at 1e9). 541 is also a twin but is claimed. 604 and 17 are different orbits of the same macro map, not trajectory twins: at 1e9 they have 18% and 23% more cells than their parents.
  • Relation (4), same class and similar growth: two weaker multi-start families. One is a Skelet 1-like Class 2 trio, a single table with 3 starts that is 5 transitions from #11. The other is an "Unknown" quartet, a single table with 4 starts that is 6 transitions from #11 and within 7% of its trajectory. Each would need a new proof, but one proof would cover all of its starts.

Method

  1. Relabelling distance. For every kill and every one of the 1,590 machines (778 representatives plus their equivalence-group members), we took the minimum, over all 720 state permutations (the start state included) with and without the L/R mirror, of the number of differing transitions (out of 12, with --- compared as a symbol). Distance 0 with a permutation that moves A means the same table with a different start, i.e. relation (1).
  2. Divergence. For each pair at distance 1–4, we ran the kill's relabelled table and the holdout in lockstep from the blank tape (a small C tool), and recorded the first step at which the holdout uses a transition where the two differ. A pair that never diverges would mean the differing transitions are unused. None qualified.
  3. Trajectories. We ran all 778 holdouts with the C core (tools/sim/tmsim) to 1e9 steps, taking the width at every 1e7 checkpoint and the nonzero count at 1e8 and 1e9. 778/778 ran, and none halted. A twin is defined as in reports/targeting.md (width within 0.3% + 3 at every 1e7 checkpoint, and nonzeros at 1e9 within 0.5% + 3). Look-alikes have width within 8% at every checkpoint and nonzeros at 1e9 within 5%. The growth exponent is log10(w(1e9)/w(1e8)).
  4. Parent-mechanism checks for the three relation-(1) machines, using each parent's own check_proof.py functions on the new start (details per candidate below).
  5. Gate. Every candidate is a byte-exact entry of the 778 list (tools/holdouts.py contains, exit 0), has no machines/<tm>/ dir, and has no completed proof in solved_index.tsv in any tier. At most it has Eqv*.v tm' mentions with proves=-. None has a sheet status, "done by", Level 1 or Unverified-tab entry, or a §7 claim. Membership in the UBRRBA (mxdys) and longitudinal (dyuan01) lists is noted but does not exclude a machine, per Dennis.

Permutation notation: perm EDBCFA means the kill's A, B, C, D, E, F become the holdout's E, D, B, C, F, A. "kill start" is the kill state that becomes the holdout's A.
