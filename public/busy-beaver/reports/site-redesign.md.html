Site redesign: build spec

Goal (Dennis, 2026-10-13): one simple, intuitive site. One nav, one page per machine, one machines table. Old URLs may break. The CLI commands keep their arguments. No information is lost: it moves.

Everything stays static HTML, written by stdlib Python with atomic writes, using relative links and no external requests. tools/serve.py stays exactly as it is.

0. Facts the spec is built on (2026-10-13)

  • 64 machine directories: 31 kills, 1 active, 1 waiting, 31 parked (8 of them cryptid candidates). 678 machines on the list are untouched.
  • 54 directories have an observe.json, so 54 have a card.html. The other 10 are delta machines with a status.json parent: 8 kills (#24, #25, #11b, #12b, W4-3b, W4-3c, W5-8b, W5-8c) and 2 that are not killed (#32, a cryptid; #23, stuck).
  • There are 30 kill.html pages. W5-4 has none, because rebuild_pages.sh never runs killreview. The new rebuild closes this gap.
  • PRs: #14, #15 and #16 are merged; #17 and #18 are open. dashboard.build_records() already groups kills per PR in meta["prs"].
  • Package folders: submission/family/ (#15, #16, #17), submission/pr/ (#18), and for #14 the older form submission/discord.md + submission/discord/. Each package holds pr_title.txt, pr_body.md, discord.txt (with placeholders), discord_dennis.txt (links filled in), attachments/*_writeup.md, images/*_spacetime_{10k,1e9}.png, and optionally forum/*.txt and names.txt.
  • All 18 decision.json files are answered, so the nav count is 0 today.
  • Cost: build_records() takes 3.0 s, of which 2.8 s is guess_class. With a 5-line list it takes 0.4 s. killreview.Ctx() takes 0.4 s, one killreview.build 0.13 s, one card.render_card 0.02 s.
  • Test baseline: test_card 26/26, test_dashboard 26/26 and test_decisions 18/18 are OK. test_killreview has 1 failure, test_automatic_checks: W4-3c has "coqchk finished" not met. That is a data fact, not a page bug, and it stays out of scope.

New tools/rebuild_pages.sh, which rebuilds everything when any input changed:

#!/bin/bash
# tools/rebuild_pages.sh: rebuild the whole site when anything it is built from changed (bb6-pages timer, every 5 min).
cd [local working file] || exit 1
exec 9>dashboard/.rebuild.lock; flock -n 9 || exit 0        # one build at a time
stamp=dashboard/.built                                      # dot-file: serve.py never serves it
changed() {
  find machines -maxdepth 5 -type f -newer "$stamp" ! -name index.html ! -name 'vs-parent*' ! -path '*/__pycache__/*' -print -quit
  find reports -maxdepth 2 -name '*.md' -newer "$stamp" -print -quit
  find data/holdouts tools -maxdepth 1 -type f \( -name '*.py' -o -name '*.txt' \) -newer "$stamp" -print -quit
}
if [ ! -f "$stamp" ] || [ ! -f dashboard/index.html ] || [ -n "$(changed)" ]; then
  touch dashboard/.built.new                              # changes made during the build trigger the next run
  nice -n 10 python3 -B tools/site.py >/dev/null && mv dashboard/.built.new "$stamp"
fi

The excluded names are what the build itself writes; without the exclusions every run would trigger the next. The rebuild costs about 15 s niced: build_records 3 s, 64 pages ≈ 5 s, then the rest. vsmode="fill" computes a new derived kill's comparison once (≈ 7 s) and caches it.
