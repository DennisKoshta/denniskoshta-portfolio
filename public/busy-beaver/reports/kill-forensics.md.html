Recent-kill forensics for Track B targeting

2026-10-09. busycoq BB6 @ 0940bb9 (2026-10-07, read-only git). Holdout snapshots data/holdouts/ (26 lists, newest 2026-10-07_778.txt + 2026-10-07_eqv_1590.txt). Sheet: data/sheet/2026-10-09_*.csv. Proof index: data/solved_index.tsv.

Hypothesis under test (Dennis): many recent kills were done with AI help. Studying them should show which areas are weak to AI, which are now picked clean, and which strategies and tarpits exist, so we don't rediscover them.

Short answer: - The hypothesis holds for the last ~7 weeks. There is explicit evidence that at least one contributor works through an AI assistant, and since Sep 2026 the kill rate has spiked in exactly the files that carry assistant-style markers. - The AI-assisted front is narrow and still moving: shift-overflow counters, Skelet-like counters, Fractal Type 7, Cubic Mess, and long halters proved with verified accelerators. Avoid those areas. - The best targets are mid-size counter/bouncer classes that cooled off in August and have reusable templates. A few small classes nobody has touched since Dec are also worth a look.

1. Method, validation and caveats

Pipeline (stdlib Python; run in this order; total runtime under 30 s):

script does outputs (reports/forensics/)
tools/analysis/forensics_git.py For every non-merge commit in ce2f22e..BB6 (133 commits since 2024-05-04): metadata, changed paths with numstat, and the machine strings each changed file newly contains (tokens in the new blob that were not in the old one), via git diff-tree -M + git cat-file --batch. Read-only, with GIT_OPTIONAL_LOCKS=0. commits.tsv, commit_files.tsv, string_events.tsv, file_first_seen.tsv
tools/analysis/forensics_attrib.py For each machine removed between consecutive snapshots: find every busycoq file that proves it (solved_index.tsv, matched by mirror/rename equiv_key, so mirrored 1LB… proofs count), find the commit that first added it to that file (following git renames), and choose the earliest proof inside the list window (Discord share dates, ±1 day). Then derive the technique family from the filename, join the sheet, and profile the 778. kills.tsv (3,656 rows, all windows since 4408), remaining_778.tsv, class_velocity.tsv, tables.md
tools/analysis/forensics_style.py AI-mention scan (commit messages, README*, every .v comment, every sheet cell) and per-file style features for the 229 proof files at the pin. ai_signals.tsv, style_files.tsv, style_summary.md
tools/analysis/forensics_report.py Joins the above into the tables used here. tables2.md

Equivalence classes. forensics_common.equiv_key is a general n-state, m-symbol normal form: halt notation, L/R mirroring, and BFS renaming of non-start states. It agrees with tools/holdouts.py equiv_key on all 12,372 snapshot machines and handles e.g. 3x3 1RB2RA1LC_2LC1RB2RB_---2LA1LA.

Validation: - Per-window reason counts match data/crossref.md §2 exactly. For example, 1003→815: 176 proof (91 exact + 85 mirror) and 12 equivalence; 1161→1119: 2 proof and 40 equivalence. - The 815→778 split matches crossref §3.1: 18 removals from 27b8b41 and 19 from 0940bb9. - Commit attribution matches git log -S. In 88 random exact-tier attributions (8 + 80), the attributing commit equals git log -S'<tm>' --reverse -- verify/<file> in every case. - The rename fix was checked. Following renames moved one kill (SOBCv11.v) from a false "2025-09 Eqv" attribution to univerz's dba975e.

Caveats: - Commit author ≠ proof author. mxdys commits other people's work. Sometimes a header carries a credit (M-Abozaid); usually nothing does. - The sheet's Results tab is stale. It is keyed to the 1534 list, and its status column stops after ~Apr 2026: 315 of 316 removals since Jun 29 have a blank status. "Done By" is only informative for Dec–Apr. - There is no Discord access. The sheet's Discord links end in Mar 2026, so "is someone working on X right now" is inferred only from commits and file headers. - "Family" is derived from the filename (forensics_common.FAMILY_RULES). The "misc named mechanism" bucket lumps BMO, BC, BL, LM, FIB, RGR, S18, InfiniteRect and others. - "Kill month" is the commit month of the attributing proof. For equivalence rows it is the month the list dropped the machine.
