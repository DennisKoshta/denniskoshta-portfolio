Counter = digit list (closes "Q language" for the aligned case)

  • Q (the cells right of the bell) is a list of digits b 0 (100)^m 0, LSB first, with bit b and length m >= 0. The 0^inf tail counts as [0,0] digits.
  • In 3-cell blocks: bits sit at cell 0, the m-track 1^m1 0 1^m2 0 ... sits at cell 2, and cell 1 is always 0.
  • The earlier encodings are special cases: 001/000 digits = [b,0]; 101 (001)^k 000 = [1,k+1]; the 1010010 D(c) prefix.
  • LP(a,n) = 0^inf (110)^a 0 (011)^n. G = LP followed by <C on its last cell.
  • <D arriving on that last cell behaves the same as <C (one step later both are in D). That is why only every other trip showed up as a G event.

Exact rules (checked against the full tape, head and state; random a up to 400, n up to 300, up to 25 digits, m up to 40)

  • T1 (one trip, n>=2): LP(a,n) <C word(D) -> LP(a+1,n-1) <X word(inc D), head on the same cell. X = C with no carry, D with a carry. 860/860.
  • The bell sweep only touches (011)^n and the a|n boundary. The right sweep enters Q as B>.
  • On Q, 1-digits are marked (b0(100)^m0 -> 11(101)^m1) and the first 0-bit is set. The left sweep restores the marked digits to 0-digits.
  • RI (n=1, D = [1,0]^j [1,m] R, m>=1): -> LP(a+2+j, m) <X word(inc R). dL = 1+j+m. 860/860.
  • The A-sweep turns each [1,0] into a 101 bell block. It turns [1,m] into the separator plus (011)^m, then carries on into R.
  • RII (n=1, D = [1,0]^j [0,m] R): -> G(0, a+2+j, 1 (100)^m 0 word(R)). dL = 1+j. 860/860.
  • A writes the 0-bit and B turns at the digit's cell 1, so the bell becomes (011)^(a+2+j) in an alignment shifted by one cell.
  • The new Q is the old word seen one cell later: a "shifted" word.
  • These three rules account for the earlier observations:
  • The odd-a G configs are RI sub-phases.
  • "dL = 1 if L even" is RII with j = 0.
  • The 2-25 spread for odd L is RI with dL = 1+j+m.

Open gap: the re-alignment race (load-bearing)

  • After RII, the shifted part is converted to aligned digits only when the counter's carry reaches it. That happens once the low aligned digits are all 1, so the lag is a power of 2.
  • A reset that meets a still-shifted Q leaves the language and can halt. Example: 0^inf 0 011 <C 11001000001000000001000101 0^inf halts at step 44 (tools/sim.py, C reads 0). 3/300 random aligned+shifted resets halted.

Notation

  • Digit (b,w) = b 0 (100)^w 0 (bit b, width w; 3w+3 cells), LSB first.
  • Junction J(m) = 1 (100)^m 0 (3m+2 cells). This is RII's output: RII leaves G(0, a+2+j, J(m) word(R)), where R is the old digits above d_j, one cell out of phase.
  • During a junction phase Q = word(A) J(m) word(R). A is the new aligned prefix; R holds the old digits.

Junction rule PROC (closes "re-alignment transient: no closed form")

  • A trip increments A as in T1. When A is all ones, the carry enters J and PROC fires:
  • PROC(m, R): R := R + m (m binary increments; widths stay with their positions; new digits have width 0); then ARR(R).
  • ARR(d:R): if d = (0,w), stop. d becomes the new junction J(w), starting one cell after d's bit cell. If d = (1,w), run PROC(w, R); so (1,0) is simply passed. ARR([]) acts as d = (0,0).
  • Output: A is zeroed, then comes ONE new aligned digit (0,x), with x = m + Σ(w+1) over the passed digits. Then J(w), then the rest of R. Exit state D.
  • Mechanism at the cell level:
  • The m blocks of J are a unary counter. Each B-arrival at R's first cell is one ordinary B> sweep in the old frame (R+1); the head bounces inside J, moving the hole one block per sweep.
  • After m sweeps, A arrives at R's first cell instead of B.
  • An A arriving on a 1-digit (1,w) gives cells identical to B entering J(w) (A1→1RF, F0→0RE versus B1→1RE, E1→0RF). That is why the rule recurses.
  • Validation: procrule.py seeds 1-5 gave 11,500/11,500 exact on the full Q cells plus exit state D, by direct simulation of the Q region (tm15.qproc). Inputs: an all-ones prefix A of up to 6 digits, m up to 40, up to 12 old digits with widths up to 15.
  • Realignment criterion: J(m) word(R) is aligned iff m = 0 and every old digit up to the top nonzero one has width 0. Checked against parse_digits: 200,000/200,000 (procrule.py 7 200000 --realign).
  • Then the old 1-runs become widths. Each old 0-bit opens a new aligned digit (0, run of 1s above it); the first new digit is (1, run0).

The race, made exact

  • Lemma B (timing). PROC pass i fires on trip 2^i - 1 of the junction phase, because A has i-1 zero digits before pass i. Re-alignment after P passes therefore needs 2^P <= L' = L+1+j. RACE_LOST means 2^P > L'.
  • Lemma A (from PROC plus the criterion). Let W = 1 + the position of the highest digit of width >= 1 above j. Then P <= max(1, W - j).
  • Reason: each pass consumes at least one digit. The first stop above the highest wide digit leaves J(0) with all remaining widths 0, and that is aligned.
  • 0 violations in 4,921,722 junction phases (invariant_scan.py 1e7).
  • Invariant Inv: W(D) <= bitlen(L) - 1, checked at resets. With Lemma A it gives 2^P <= 2^(bitlen L - 1) <= L < L', so the race is won. Preservation:
  • T1: W is fixed and L is unchanged. RI: W drops by j+1 and L grows. OK.
  • Junction phase in which no PROC addition carries past the top of R ("no overflow"):
    • The realigned D is P aligned digits plus 1 + zeros(R_final) tail digits. Each pass consumed at least one digit of R.
    • So W' <= |R| = max(W, bitlen V) - j - 1 <= bitlen(L) - 1 <= bitlen(L') - 1, using V <= L, which always holds. OK.
  • Junction phase with an overflow: W' can reach |R| + (number of appended digits), which can break Inv.
    • An overflow needs the rest of R to be all ones when the junction reaches it. So it happens only when V's top bits are a long run of ones, near L ≈ 2^k.
    • Overflow phases cluster at octave crossings: 4,303 of 4,921,722 junction phases to 1e7 phases, none between L = 1.9e7 and 2.6e7.
  • If overflows never broke Inv, non-halting would follow by induction from the start config, given cell-level proofs of T1, PROC, RI and RII. The open part is therefore only the aftermath of overflows.
  • invariant_scan.py results:
  • Inv is violated at 3 of 1e7 resets: RI at L = 11, RI at L = 4,193,607, and RII at L = 4,193,612. All 3 came right after an overflow phase, and only 1 was at an RII.
  • That one RII is at L' = 4,193,613: W = 22 = bitlen(L'), j = 0. The race was still won, with P = 6 against the bound 22, because the junction passed the top run of ones in one ARR without carrying.

Closest race (load-bearing near miss)

  • Phase 703,380: RII at L = 4,193,611 (L' = 2^22 - 692). V = (L+1)/2, j = 0, J width 15. Widths [15,3,0,11,0,0,1,0×13,1]: the top digit (position 20) has width 1.
  • Pass 7 adds 1 to a remaining R of 13 ones, which overflows into 13 zeros. Each zero then costs one pass, and the width-1 top digit forces the junction all the way up: P = 21, re-alignment on trip 2,097,151 of 4,193,611.
  • Margin log2 L' - P = 0.9998 bits. nearmiss_check.py replays all 21 passes at the cell level, exact.
  • That phase leaves Inv broken: W = 22 at L' = 4,193,612 (above).
  • A loss would need the next junction to stop just below the top run of ones on a digit of width >= 1. Here that digit (position 9) had width x = 0, because the passes through the overflow zeros all have x = 0. Whether that protection always holds is open.
  • Margin per octave (race_scan.py 1e7):
  • The minimum is 2.3-5.6 bits in every octave from 2^8 to 2^26 except 2^21 (0.9998).
  • The P distribution creeps up about 0.25 per octave, and its upper tail falls about 3x per extra pass.
  • Synthetic Inv-violating V = L configs (L = 2^k - s, wide top digit, random low widths): 1 race lost in 38,136 (k = 22, 30, 40). So even after a broken Inv, a loss needs a second coincidence.

What a lost race does

  • The race is never lost naturally to L = 6.9e7, so these runs force one by stopping the closest race early.
  • raceloss_reentry.py stops the closest race after k passes and resets with a small bell:
  • 21/21 configs ran 3e6 steps without halting. Each had a few OUT G configs and then returned to DIG/ALS.
  • A wider sample from the same phase had 4/388 halt within 2e6 steps, after 208, 208, 815 and 29,740 steps. Round 1 found 3/300.
  • So halting needs a lost race (very rare) that is also a fatal one (a minority).

Why cryptid

  • The rules are now complete and exact. The halting question reduces to whether a rare arithmetic coincidence ever happens at some octave crossing L ≈ 2^k: 1. an overflow junction breaks Inv; 2. at the next RII (V = L, j = 0) a carry runs through the top run of ones before the junction passes it; 3. the resulting lost race is fatal.
  • Steps 1-2 depend on the widths x = m + Σ(w+1) and on low bits that build up over the whole history. No conserved quantity was found that controls them. That is the pseudo-random arithmetic of the cryptid protocol.
  • Heuristically the per-octave loss chance is about 1e-5 and the fatal fraction is a few percent. Whether that chance shrinks with k decides "probviously non-halting" versus "halts astronomically late"; it is not settled.
  • Route if Dennis says continue:
  • Prove the overflow-aftermath lemma. After an overflow junction, the overflow zeros come back as x = 0 widths. Show that the next junction cannot carry into the top run before passing it, or that RI phases restore Inv first.
  • The data supports it (1/1 natural case), but the argument must survive RI shifts and increments between the phases.
  • Everything else (T1, PROC, RI, RII, realignment, Lemmas A and B, Inv preservation without overflow) is ready for proof.md.
