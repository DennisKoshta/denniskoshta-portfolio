Mechanism

Words: every long run is a power of a 4-cell word, either a 3-ones word (rotations of 0111) or a 1-one word (rotations of 0001). The head sweeps the whole tape; a right sweep turns 1-one words into 3-ones words and the left sweep turns them back.

  1. Visit level (compress). Between events a marker crosses a run one word per left-end visit and turns each word it passes into two words on the other side: (0100)^a 11 (0001)^b goes to a+2, b-1 per visit (75 visits in a row at 1e9). That is the doubling transfer b -> 2b + c. Other phases add a small run to the big one (Z -> Z + const) or move the big run across a separator unchanged.
  2. Segment level (qsim records). Each qsim rule application ends a segment whose big field changes by Z -> a Z + b with a in {1, 2, 4}. No segment ever halves a field.
  3. Cycle level (175). From record 21 (step 4,111,147,719,584,449,981 = about 4.1e18) the record sequence is exactly periodic with period 42: M(X) = 0^inf 1 1011^X 10111110 1110^26 <A 01010100010000010001000100001 0^inf M(X) -->+ M(2^36 X + 9575900996480). All other fields in the period are constants (26, 28, 80, 78, 20, 18, 16, 82, 12, 10, 8, 922, 6, 1004, 2020/2024, 4072/4074). The map holds exactly for all 56 observed periods, starting from X0 = 508,932,080; X_k ≡ 0 (mod 64) for k ≥ 1 (X0 ≡ 48), and 2^36 X + c keeps X ≡ c (mod 2^36), so every parity condition inside the period sees the same residue every time.
  4. Base-level validation (scripts/segval.py, work/segval175.json). Each of the 42 segments of the period was fitted as Z -> a Z + b (exact over all observed periods) and then re-run by plain TM simulation from the constructed configuration with small random Z of the same residue mod 64: 165/165 passed (every segment 2-4/4). The composite of the 42 fitted maps is X -> 68719476736 X + 9575900996480 = 2^36 X + 9575900996480, the same as the observed one. A mod-4 rerun with Z in 30..300 (work/segval175_mod4.*) was still running at write-up; the start X0 ≡ 48 (mod 64) already shows the period needs at most X ≡ 0 (mod 16).
  5. The parity-flagged rules (stop-rule check). qsim's 3 collatz-flagged rules on 175 (15, 37, 58) eat a left field two words at a time (01110111^-2 per application) while a right field loses 1. Rules 37 and 58 are used once per period (119/118 uses in the planner's 90 s run, about 119 periods); rule 15 is transient only. Every field in a period is either a fixed constant or an affine function of X with X fixed mod 2^36, so the field these rules consume two at a time starts each period at the same value or the same residue, and the endpoint parity is fixed. The 42-segment base validation (point 4) covers both rules' segments.
  6. 489 is in a different regime. Its far end (mirrored, on the left) holds two huge fields Y1 = 939,468,133,961,604,904 and Y2 = 10,456,559,309,013,950,600 (record 183). The record sequence is periodic with period 40 (8 rounds): D(Y1, Y2, X) -> D(Y1 - 48, Y2 - 240, 2^40 X + 377451701380050). Y1 runs out first, after 19,572,252,790,866,768 periods (Y1 mod 48 = 40; Y2 mod 240 = 200; Y2 is then 5,759,218,639,205,926,280), with X about 2^(7.8e17). Earlier, 489 already pushed one accumulator into its far end (4 90 X18 -> 64 X18 242 8392), i.e. the "big block becomes the far-end digit list" event, so its depth grows like a tower. What happens when Y1 runs out is unknown: it can only be reached symbolically (residues of Y1, Y2, X).

One argument for all starts?

No. 175 reaches the one-field cycle M after a short transient (21 qsim records, about 4.1e18 steps). 489 has two far fields of size 1e18 and 1e19 that are consumed linearly at tower depth; whether it ever reaches M (or halts) is decided by the exhaustion events of those fields, which the plan's "differ only in high digits" did not anticipate. A delta for 489 needs new rules (the D-regime and its exhaustion events), so by the plan's delta rule it stops; it is filed as a separate park-or-fund decision (decision.json).
