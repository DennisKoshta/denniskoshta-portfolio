Summary

The scout's premise was a near-port: this is TM10 with A1 changed, and A1 is used only at step 10.

That premise is wrong in one important way. ROv3_0/ROv3_1 are false for this machine, not merely unproved. TM10's invariant P contains halting configurations: cfgL(8,0,17) satisfies P and halts at step 10,189,718.

From blank, the run stays inside TM10's "normal cycle" for as long as one digit condition holds. The condition is that the counter value x has a 1-bit at an even position. Whether that holds forever is a question about the binary digits of an exponentially growing orbit. That is ground rule 6, so the machine is flagged CRYPTID_CANDIDATE with a priority call.

The cycle from blank

The run reaches cfgL(3,6,1) at step 35. After that, every cycle between left overflows looks the same.

  1. cfgL(L,0,2x+1), then LOv. Here n = 2x+1 is odd, so i = 0 and the run goes to R1(L, 2^L-1, 0, 0, x).
  2. RC1_Ov_0 with lenR = 0, giving R4(L+1, 2^(L+1)-2, i1, 2^(i1+1)-2, x1), where x = (2x1+1) 2^i1.
  3. A chain of RC4_Ov_1 steps runs while the current gap i is odd. Each step consumes the next 1-bit of x.
  4. RC4_Ov_0 at the first even gap i = 2q gives R(L', K, 2m+1).
  5. RInc and the LC/RC run lead to the next cfgL(L', 0, 2x'+1).

The new value is

x' = (2 k_c + 1) 2^(5q) + m

where m is x with the consumed bits shifted out, and k_c is the left counter after the chain. N stays odd, so the corner case (n = 2^L) and R1 with lenR > 0 never occur.

The chain stops at the first 1-bit of x at an even position. It empties (RC4_Ov_1_0) iff every 1-bit of x is at an odd position.

The closed form is F in scripts/Fmap.py. It reproduces the macro-rule simulator (scripts/absm.py) on 783 consecutive cycles.

  • 20,000 cycles computed, with L up to 172,193 (TM steps roughly 2^172000). The chain never empties.
  • E = number of 1-bits of x at even positions:

  • Chain lengths: 13,650 × 0, 4,120 × 1, 1,588 × 2, 440 × 3, 150 × 4, 38 × 5, 9 × 6, 4 × 7, and a single 28 (cycle 14,614).
  • Stop values: q = 0 in 72% of cycles, q = 1 in 20%.
  • New 1-bits enter at the top of x. For a chain of length 0, the gap between the new top bit and the previous one is 7q+4: even when q is even, odd when q is odd.
  • Older bits move down and are consumed by later chains. A run of q = 0 cycles leaves a run of same-parity bits, and a later cycle eats that run in one long chain (the 28).
  • So x is a queue that feeds on itself: what is appended depends on what is read at the bottom.
  • The bottom bits are mixed by the - (2^(i+2)-1) 2^(5q) borrow each cycle. They look random (Fig 2).

Heuristic (cryptid protocol)

If x's 1-bits were independent fair coins for parity, the chance that cycle t empties the chain would be 2^-(1-bits of x_t). That is at most 2^-17 from cycle 4 on, and it falls exponentially, since the number of 1-bits grows linearly. Cycles 1..20,000 are checked exactly.

So it is "probviously" non-halting. But non-halting is equivalent to a statement about the digits of an explicit arithmetic orbit, of the AntiHydra kind. No invariant was found: - E has no monotone bound. - The highest even-position 1-bit sits up to 19 bits below the top. - Gap parity is fed back from the pseudo-random bottom bits.

TM10's own orbit

From cfgL(5,19,1), TM10's chain empties once, at L = 11 (RC4_Ov_1_0). The continuation then has an even gap and returns to normal cycles, so it never reaches R3. TM10's proof does not care, because its ROv3 lemmas hold. The two orbits never merge.

  • The scout compiled TM10's module with this string and init cfgL(3,6,1). Everything except ROv3_0/ROv3_1 compiles.
