Outcome: no halt up to step 5.636e76 (10^76.75) (exact model, validated against direct simulation on every anchor reached). Not a kill and not a halt.

What was built (work/exact/)

  • xm.py: an exact accelerated simulator. Nothing is fitted; every rule comes from the transition table.
  • Tape = tokens: literal cells, or runs w^n (word of period 1..16, exact big-integer count).
  • Literal cells: plain TM steps.
  • Shift rules: when the head enters w^n in state q, the TM is run on one copy of w plus k context cells (k = 0..24). If the head leaves on the far side in state q and the region now reads C w' (resp. w' C), induction gives w^n C -> C w'^n in n*s steps. Constant runs with no rule for w also try w^2..w^4.
  • Peeling one copy when no rule exists.
  • Memos: a symbolic run of the same engine over a suffix region [b, E) of the tape. Counts >= 16 become symbols, the right of the region is treated as blank (E = the first long 0-run), the run starts with the head about to enter run r leftwards and ends the first time it is about to enter run b leftwards. Every peel and every nested memo adds an affine constraint. A memo stores the result tokens (affine counts), the step count (affine), the blank cells it uses and its constraints. It is applied only when the region shape matches exactly and every constraint holds; a memo whose symbolic run reaches a halting transition is discarded, so halts are always met concretely.
  • The recursion (memo for b uses the memo for the next run right of b) is what batches the binary counter: each level costs about 4 applications of the level below.
  • Drivers: far2.py (far run with JSON log + state pickle every 5 min; --tm, --ckpt, --resume), anchors.py (exact comparison with R5CFG references), postcheck.py (comparison with an r5run continuation), loadcfg.py (tokenises a 1e8-cell checkpoint exactly), test_blank.py.

Epoch 2, as the model sees it

  • At the checkpoint (rel 2e13) the tape is a static left part, several finished sub-counters separated by period-8 runs ((11101010)^n / (11010101)^n), the active counter, and the epoch-1 debris: short blocks at x4-spaced positions (zero gaps 12,819 / 73,715 / 294,899 / 1,179,635 / 4,718,579 / 18,874,355 cells) and 1^7 at the old right end.
  • Each sub-counter is the epoch-1 kind of binary counter (segments (110101)^n, x4 per segment, gadgets of about 100 cells). The finished ones end with a big segment S followed by (11010101)^~2S: S = 196,607 / 786,421 / 3,145,733 with runs 393,167 / 1,572,810 / 6,291,263. Reading: a sub-counter runs until its right end meets the next debris block, then its last segment is converted and a new sub-counter, one level bigger, starts to its right.
  • Past the last debris the active counter grows freely. Its fuel is the run (11010101)^6,291,263 to its left, eaten as new top bits are made (as epoch 1 ate (10)^66): it went 6,291,263 -> 6,291,195 -> 6,291,133 -> 6,291,121 -> 6,291,118 at steps 10^44.95, 10^59.70, 10^73.14, 10^75.84, 10^76.61: steadily about 4.6 copies per decade of steps.
  • The finished sub-counter to its left (segments 9 .. 3,145,739) is incremented while this happens: its low gadgets flip (10)^9 <-> (10)^1 and its last segment grows 3,145,733 -> 736 -> 739 over the same span. So epoch 2 is a counter of counters.
  • No overflow of the active counter happened in the run. At the measured rate its fuel lasts about 6.29e6 / 4.6 ~ 1.4e6 decades: the next decision point (the active counter's overflow) is projected near 10^(1.4e6) steps (an extrapolation, not a model result). The left counter's own overflow is also far off (ten levels; its lowest segment grows by 3 per ~14 decades).
  • Cryptid check: none. Everything seen is binary counting with periodic fuel use; no parity- or Collatz-like branching.
