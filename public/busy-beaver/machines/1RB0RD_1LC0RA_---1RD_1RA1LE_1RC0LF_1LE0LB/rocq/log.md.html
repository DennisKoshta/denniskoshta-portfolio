Round 1 (2026-10-12)

Design decision: hybrid engine instead of hand-written structural rules (changes plan section 4)

Measured on the real run (scratchpad scripts, numbers reproducible from work/fast.py): - 53,973 structural increments; 53,805 batches. - Carry paths of the structural increments contain 88.1M wall/gap tokens in total (max config 2,990 tokens). - Event unit: U0 in 25,150 increments, U1 in 26,179, others ~5k; the event unit's marker count summed over all structural increments is 19.9M (max k = 1,342).

So: - The plan's call1 needs ~15 structural lemma families (glue, unglue g=1/g>=2, absorb, edge1, U0-1111, U0-stop, resets, glue-after-unglue) plus canon re-cut lemmas. That was the plan's risk #1 and #2. - A purely generic run-length simulator (busycoq Sk1Tape.Runs + RunMachine.raw + Sk1 scans) needs no structural lemmas but would take ~1e9 macro steps (88M tokens x ~10 steps): too slow. - Chosen (B'): generic engine on RunMachine.config for tmf (Sk1Tape/Sk1Check machinery: raw steps, scans with context), plus verified macro rules that skip a whole standard unit (unit segRR/segLL/segRL) or a whole passive block (block segRR/segLL), plus auto_bulk at the root (the batch). Structural events then need no lemma at all: the event unit is simulated by raw steps + scans + block macros (cost ~ sum of k of event units ~ 20M macro steps, plus ~25 unit macros per structural increment). Opening (342 steps) and the halt itself are also done by the engine (RM.raw returns None = halted). - Untrusted proposals (parse of the Runs into unit records, batch size d) need no proofs; every use is checked by Runs.remove-style word removal (Sk1Check.remove_cells pattern) whose spec is generic.

Call protocol, block level (found with mcap.py, confirmed by solve_seg)

Mirror machine tmf, words near-first. A unit (root-first) = prefix ++ lead ++ x-gap ++ boundary, where prefix = Y block (y gap + last passive) followed by the chain of passive blocks (gap + stack), all of shape blk m j = [0] ++ [1;0]^^m ++ [1] ++ [1;1;1]^^j; k=1 digits have an empty prefix. - Y block: out B->F, back D->D. Chain blocks: out F->F, back D->D (LL cuts are shifted 2 cells root-ward; this is what lbw m j = [0;1;1]^^j ++ [0;1]^^(S m) encodes, and cmid_shift re-associates). - Lead 1111 (= blk a 1): out F->F (or B->F for k=1); back A->D. Lead 00 stop: F->D (B->D for k=1). - x gap + boundary 11 after a 1111 lead: out F->B, back D->A, word unchanged. - U0 far region (x gap + edge 1^(3f)), e = 0 mod 3: side F->D, edge f -> f+1. - Unit level: in B, out B, back D, return D (hB/hD, h = [(hB,hD)]), as in the plan.

Round 2 (2026-10-12)

Design change back to structured records (supersedes round 1's hybrid engine)

  • rocq/tools/kinds.py (full run, ~5 min) classifies every touch of the 53,973 single increments by the lemma family it needs. Event units are mostly U0 (leadless, Pascal rows, k up to 1,342); a generic engine would pay O(k) macro steps per event (sum ~2e7). Records pay O(1) (O(k) list append for unglue).
  • Key fact (found with the probe tactic, rocq/r2/probe_hdr.v): in the mirror every touch of a unit consumes the two root-most cells [0;1] of the unit word ("all passive walls move 2 cells root-ward"). So with uw bs b a x far = cw bs ++ leadw b a x ++ far (bs = passive blocks root-first, blk c j = gap 2c+1 then 1^(3j+1)) every family is consume of a block list: c>=1 -> c-1; c=0 -> glue (overhang [1;1;1]^^j into the root-side boundary, re-cut = tailw g ++ [1;1;1]^^j = tailw (g+j)); bs=[] (k=1) -> the lead's own gap a-1.
  • Families (all proved, rocq/r2/A1.v A2.v, compile 7 s): t_stop, t_pass, t_ungl1 (bs ++ [(a,1)], new lead lead0 (S x) 1), t_ungl2 (bs ++ [(a,1);(x,g-1)], lead0 0 1), t_halt, z_lead (leadless U0 + edge), z_empty, z_absorb (edgew 0 (S f) -> [1;1] ++ [1;1;1]^^(S f)), z_stop (U0 digit, class-1 edge), z_1111 (U0 digit lead 1111 + edge1: bs ++ [(a,1);(x,f)], new edge 111), reset1 (root with 1^5 tail -> NT), reset1_halt, reset2 (NT -> root 0). Generic composition: gen_RL/gen_RLg, gen_fwd/gen_fwdg, gen_side/gen_sideg (prefix out B->F, core in F, prefix back D->D, glue variant via prefLL_glue); B-entry cores coincide with F-entry cores (checked per core).
  • N-level: unitN/zN/tailN/cfg, consumeN (+spec), touchN (+ stop/pass/halt specs) compile (rocq/r2/B1.v).
  • Call/increment layer (rocq/r2/B2.v): ztouch (+ret/abs specs), callN (+callN_ret, callN_halt), inc1 (+inc1_ok, inc1_halt) incl. reset1/reset2. Batch layer (B3.v, B4.v): pairK, pair1, clK0/clK1/cl10/cl11, closedU_spec, zLs/zEs, closedZ_spec, batchL_spec, propose (untrusted), batch_step_spec, next_spec, check_spec.
