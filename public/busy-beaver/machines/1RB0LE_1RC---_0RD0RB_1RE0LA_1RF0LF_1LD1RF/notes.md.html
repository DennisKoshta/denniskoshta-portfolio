Frames and words

The state map from ours to SOBCv10 is A,B,C,D,E,F -> D,E,F,A,B,C with a mirror. So our machine is SOBCv10's machine started in SOBCv10's D. Everything below is written in SOBCv10's frame (its wall on the left), because that is how its lemmas read. Our own frame is the mirror image: fossil and counters on the left, the tally growing to the right (Fig 2).

A hash is one signal: SOBCv10 B> at the left end of the word region (our <E), returning as SOBCv10 <F (our C>).

Mechanism (same as SOBCv10)

  • The left part W X^u is a tally: every returning hash walks to the wall and back and adds one X (left_emit_call). Steps grow like u², which is why direct simulation sees so little.
  • To its right sits a binary counter of A/B digits (least significant next to the head) that each hash increments. Its overflow carries are absorbed by marker words further right (D -> A grows the counter, C A U U -> D C A eats a U pair, ...).
  • When the counter and everything behind it is all B and the carry reaches the edge t, an exception fires: the tally turns into exactly n = (u-1)/2 fresh hashes, which are fed into the rewritten counter (E^w A, a mixed-radix word), and the result is W B> C A U^(2n) output (exception_done). The C A U^(2n) block then needs 2(2^n - 1) hashes to drain (cd), so each exception makes the next one exponentially later.
  • SOBCv10's own start passes 4 exceptions and then enters its round invariant (post_ca_state + sobc1_round_invariant), where each round adds one binary column.

The tail as one digit with levels

The tail is U^(2k+1) y after the last column. U passes hashes through unchanged, so y acts as one more digit. It has six levels:

level -1 0 1 2 3 4
y A (no t) B (no t) E t D t A t B t

A carry into the tail raises the level by one. A carry that arrives at level 4 is the exception trigger.

Three laws

T1, timing. Count the digits as A = 0, B = 1, D = -1, E = -2, with the tail level at weight 2^W (W = number of digits before the tail). Call the total V. Each hash adds 1, and the trigger can only come when everything is B and the tail is at level 4. So the trigger is hash number

5 * 2^W - V        (SOBCv10's own count is 3 * 2^W - V)

modelA.py: 80/80 random instances, including tails at levels -1 and 0.

T2, raw pass. The exception's raw return turns

B^w U^(2k+1) B t   into   E^(w-1) U^(2k+3) y,   level(y) = k - 1   (k = 0..5)

The last column loses its top digit, and the U run grows by one pair. For k >= 6 the return overflows the tail. rawlaw.py: 48/48 for k = 0..5 (1-3 columns, widths 2-9); 16/16 overflow cases for k = 6..9 end in the cycler below.

T3, decode. Let L be the effective tail level: the level minus any deficit left in the last column. By T1 and SOBCv10's frontier count,

n = n_s + (2 - L) * 2^(W-1)

Here n_s is SOBCv10's round_next_half for the same columns. The n_s part decodes exactly as in SOBCv10. Its last column ends below 2^(w-1), so nothing reaches the top digit, which is the eaten one. The extra part gives 2 - L carries into the tail. If L > 2, the truncated last column is instead left short by L - 2 levels (pre-state E/D digits).

modelD.py checks the whole exception (raw pass, launch, decode) against T2 plus a segment decode of n hashes on 25 random cases. 23 match; the other two are not decodes: one decode trigger (see below) and one n = 0.

Per exception, then:

L' = k + 1 - L,   k' = k + 1
last column: width w -> w - 1,  value v -> 2^(w-1) - floor(v/2)
the decode triggers  iff  (k - 1) + (2 - L) >= 5

with blank to the right. Every 919 steps it moves 3 cells right and never reaches more than 67 cells back. Checked over 2,000 periods with random junk to the left. In our frame it is the mirror image, a cycler running left.

How the toys get there (trigtrace.py and sweeps2.c, k = 4, n = 900, columns 2, 2, 3, 2). This is not a short epilogue: the trigger starts a second counter phase.

  1. The trigger's return turns x x pairs into D going left as far as the 1 0 marker, then comes back.
  2. Phase P1, 256 long sweeps. Each sweep runs from the 1 0 marker to the right end, ticks a counter made of the old columns (now written in B D / U C / B U / U A patterns), takes 2 v from the pending-call block on the left, and adds 2 x.
  3. Phase P2, about 200 shorter sweeps, with the left block frozen.
  4. The counter runs out at the right end, and the 919/3 cycler starts there.

P1's length (256) is the same for n = 874 ... 2,000. At n = 874 the v block runs out exactly at P1's end. That run takes another path through the wall and still reaches the same cycler (sweeps2_n900.out shows the n = 900 run).

P1 law so far (p1fit.py, k = 4, n = trigger + 300): P1 = 2^(W-1) sweeps, W = P + sum of the column widths at post_ca. The layouts tested were 2 | 2,2,3,2 (1,024), 2 | 2,2,2,2 (512), 2 | 2,2,3 (256), 2 | 3,3 (128), 2 | 2,4 (128) and 3 | 2,2,3,2 (2,048). So for k = 4 (the exception-9 case) P1 is one full cycle of the truncated columns. P1 depends on k. For 2 | 2,2,3,2 it is 1,024, 3,072 and 4,096 for k = 4, 2 and 1, so

P1 = (5 - k) * 2^(W-1)

This is what T1 and T2 predict if the decode trigger acts like an ordinary trigger for the tail. Its return grows the U run to U^(2k+3) and leaves the tail at level k, and the counter then needs 5 - k full cycles to trigger again. So the run after a decode trigger looks like a short series of nested triggers, each growing the U run, until a raw pass overflows (k >= 6).

In exception 9 (k = 4) that is one cycle, then a trigger with U^13, so k = 6: overflow. P2, which comes before the cycler in the toys, is not explained yet. P1 uses 2 v per sweep. In the 2 | 2,3,2 runs (W = 9, P1 = 256) the v block at the trigger is 2n - 1,239 = 2^W - 3 + 2 * (pending calls). So it is just enough for P1, except for the last sweep or two when no calls are pending; that run takes the wall path and still reaches the cycler. Whether 2^W - 3 + 2 * (pending) holds in general is not yet checked. P2 (131 ... 1,855 sweeps) has no fitted law yet.

At the real sizes this is a race between the P1/P2 counter (old columns, huge widths), the x fuel (finished calls) and the v block (pending calls). Every small case ends in the cycler, including the boundary ones, but the race is not computed.

What this changes

  • There is no tail-aware infinite round invariant. The SOBCv10 rounds stop at exception 9, so the stage-0 plan (generalize sobc1_round_invariant) is dropped.
  • Not a cryptid: every step is counter arithmetic with a fixed exit.
  • Proof route: opening (families (a)-(d)), then 4 explicit tail-aware SOBCv10 rounds (exceptions 6-9), then the decode trigger in exception 9, then the second counter phase (P1, P2), then a translated-cycler lemma (window above, period 919, shift 3).

Still open

  • Families (a)-(d) at the real sizes (m = 30, p = n4) are still extrapolations.
  • T1-T3 are checked on small instances only:
  • T1 is a counting argument;
  • T2 is six concrete raw-return lemmas, k = 0..5 (only k = 1..4 are used);
  • T3 follows from SOBCv10's round_output_required plus a carry-shift lemma for the last column.
  • The run after the trigger is a second counter phase (P1, P2 above). At the real sizes it needs its own law, a parametric sweep lemma per tick, and the race against the v and x blocks. This is the hardest new part, and the one place a different ending (another exception, or a halt) could still hide.

The exit, step by step (SOBCv10 frame)

After a raw pass of an all-B counter, the word is E^(P-1) A, then E^(w_j-1) A per middle column, then E^(w_m) for the truncated last column. Its value is 2 - 2^(W+1) + S, with S = sum of 2^(offset) over the non-primary columns. So by T1, with tail level λ, the next trigger is on hash

h(λ) = (7 - λ)·2^W - S - 2
  1. Decode trigger. Exception 9 (λ = 3) triggers on call h_t = 4·2^W - S - 2. By T3, n9 = h_t + c, where c ≥ 0 is SOBCv10's decoded column value, so the trigger always happens, with c calls pending.
  2. E′. The trigger's raw pass is T2 with k = 5: the tail becomes U^13 B t and the last column loses another digit (25 → 24). The return finds 101 ++ X4^(2f+5) = 1010 ++ V4^(2f+4) ++ 010, which is exception_pre_left (f+1) with another far end. So E′ has n′ = f + 1 = h_t calls, and exception 9's pending calls are frozen behind it.
  3. E″. E′'s counter has W - 1 digits and λ = 4, so E″ fires on E′ call h″ = 3·2^(W-1) - S - 2. That is (5/2)·2^W calls before E′ would run out.
  4. Overflow (k = 6). E″'s hash walks right over the all-B counter (raw_B_forward, raw_U_to_X). From l B> B^w U^13 B t 0^inf (w ≥ 1) the machine reaches the cycler window Y in 1208 + 14(w - 1) steps and never visits l.
  5. Cycler. L Y B> 0^inf → L 100 Y B> 0^inf in 919 steps for every L, never visiting L.

Robustness

The levels in the chain (3, -1, 4, 0) decide when the run leaves the rounds, not whether it leaves:

  • k grows by one per exception, nested ones included.
  • An inner exception always reaches its own trigger: it gets (8 - k)·2^W - S - 2 calls and needs (7 - k)·2^(W-1) - S - 2.
  • A raw pass at k = 6 always overflows into the cycler.

So the exit comes by exception 11 at the latest. Stage 1's decodetrig2 (60/60, k = 0..5) agrees.
