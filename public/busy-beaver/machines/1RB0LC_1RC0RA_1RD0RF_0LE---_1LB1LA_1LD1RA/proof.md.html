0. What the machine does

The tape is one bouncer that runs between two growing regions.

  • Left-turn frame. The head is in A, reading the 0 just left of the active word Y. To its left is either
  • a stack of "walls" X plus a run (10)^P, or
  • the blank edge.

To its right are Y, a run (010)^d and a list Z of pending chunks. - Each round trip sweeps right across Y to the (010)-run, eats two (010) units, and sweeps back. - Each trip takes (10)^2 off P, or, at the blank edge, extends Y to the left. - The run that the eaten units feed grows by 2. - When d runs out, the next chunk merges into Y, or (with d = 1) is eaten. - When P runs out at a wall, one of two things happens: - the bouncer pushes its whole Y as a new chunk and restarts on the wall (Push); - or it absorbs walls by a binary carry (Absorb). - When d and Z are both gone (a "right end"), the rightmost (10)^ak-run feeds a Jacobsthal staircase: busycoq's FractalType4 TM5 lemma P. The staircase lays out the next (010)^d-run, and the old Y becomes the new wall stack.

Halting needs the right sweep to meet the pattern B> 0 0 1 (§6). In the grammar this happens only when an odd (10)-run inside a chunk gets eaten. A parity invariant excludes that, but the invariant also has to carry linear facts that link the walls to the staircase level (§5).

2. Notation and families

Words are written left to right. Two head markers are used: - <S: the head is in state S, reading the last cell of the word to its left; - S>: the head is in state S, reading the first cell of the word to its right.

Block names: - (10): pair; - (011010): six-block; - (010): triple; - (101): wall cell triple.

Staircase levels. S_0 = 0 and S_{j+1} = 2 S_j + 3 if S_j is even, 2 S_j + 2 if S_j is odd. This gives 0, 3, 8, 19, 40, 83, 168, 339, 680, 1363, ... For n ≥ 1, Sof(n) is the largest level ≤ n − 1.

Active word. Y = (10)^a0 (011010)^b1 (10)^a1 ... (011010)^bk (10)^ak, with k ≥ 0. It is written Y = [a0, b1, a1, ..., bk, ak]. B = Σ b_i and A = Σ a_i. A "segment-less" Y is [a].

Chunk. C = (011010)^B1 (10)^A1 ... (011010)^Bm (10)^Am (010)^c. Chunks are listed nearest first in Z. A chunk with c = 0 is glued to the next one. Zero inner runs glue their neighbours ((011010)^b (10)^0 (011010)^b' = (011010)^(b+b')). Both are tape identities.

Walls. X = (10)^p1 (101)^q1 ... (10)^pm (101)^qm, listed far to near. An interior wall with p = 0 is glued to its left neighbour (normX).

Families. Two kinds of left-turn frame:

P-mode  F_P(X, P, Y, d, Z) := 0^inf X (10)^P <A Y (010)^d Z 0^inf      (a0 = 1, P >= 1)
edge    F_E(Y, d, Z)       := 0^inf <A Y (010)^d Z 0^inf

Virtual frames. These are P-mode frames with P ∈ {0, 1} next to a wall. They are not left-turn frames of the machine: the cell two left of the head is a wall cell. They occur only inside composite rules (§4.3):

V1 := 0^inf X (10)^p (101)^q (10)^1 <A Y (010)^d Z 0^inf
V0 := 0^inf X (10)^p (101)^q <A Y (010)^d Z 0^inf

Right end. A frame with d = 0 and Z empty, written R = (mode, X, P, Y). Three kinds exist in the rule set: - an E hub 0^inf <A Y 0^inf; - a P-mode right end without walls, 0^inf (10)^P <A Y 0^inf; - a P-mode right end with walls, 0^inf X (10)^P <A Y 0^inf, X nonempty.

The rules of §4.4 handle all three. The third kind does occur: from long Level hubs (e.g. [35,13,30,14,18,2,40]) and on the short chain from the E hub [79,12,32] (§8 G1). The invariant of §5 admits only the first two kinds (clause H0), so "right ends in the invariant have no walls" is a clause to be preserved, not a fact about the rules.

Base. K0 := F_E([85, 7, 46], 0, -) = 0^inf <A (10)^85 (011010)^7 (10)^46 0^inf, reached at step 46,734 (§7).

5.1 Hub coordinates

Every right end R without walls (except a segment-less hub) gets a flat sequence z = (z_1, ..., z_2m) and a scale τ.

  1. Take the walls V of §4.4 in order.
  2. Add one virtual last pair, the start frame's fresh bouncer: - Clean: (ak − S + 1, S − 1), with τ = S − 1; - Level: (1, ak − 1), with τ = ak − 1; - Top: replace the last pair (p, q) by (p, q + ak), with τ = ak.
  3. Define the tail sums

B(k) = Σ_{l ≥ k} (−1)^l z_l

so z_2m is counted with sign +.

"Short" means m ≤ 2, that is, at most one real wall. "Long" means m ≥ 3.

Lemma T (traversal as a stack process). Status: fitted, not derived.

Hypotheses (all needed; the skeptic's counterexamples break each one that is dropped): - R is an E hub or a P-mode right end, with no walls; - R is Clean or Top. A Level right end with ≥ 2 real walls is excluded: [35,13,30,14,18,2,40] has B(3), B(5), B(7) ≥ 0 and still ends its traversal in a P-mode right end with a wall; - every restart at a wall has P odd, so the bouncer pushes or merges and never absorbs. This holds when every real wall is even/even, which is H1 (a0 odd, inner a even); a P-mode right end's collapse wall is odd/odd and gives a P-even restart, which absorbs. So in P-mode the statement covers the walls after the first one only.

Statement. Write Δ = d − P. During the left traversal of the walls: - at a wall with Δ ≥ 1, Push stores a chunk with Δ − 1 triples and restarts with δ_i = q_i − p_i + 1; - with Δ ≤ 0, BounceP runs d down and the top chunk is merged or eaten.

The running sum is T_i = 1 + B(2i − 1). Hence: - B(odd k ≥ 3) ≥ 0 means the traversal does not end while walls remain; - B(1) < 0 means the traversal ends in a P-mode right end (a collapse).

What is derived. The push step is derived from the rules: at P = 3 BounceP31 leaves d − 2 at V1, and Push1 stores d − 4 = Δ − 1 triples (§4.3). The restart value δ = q − (p − 1) is read off Push1. The merge step is a tape identity. What is not derived is the accounting through eats (EatChunkP changes P by 4B + 2A, which must cancel against the chunk's contribution to the B sums), and the identity T_i = 1 + B(2i − 1) as a whole. That is gap G2.

6. Progress and halting

Progress. Every rule of §3-§4 is a run of ≥ 1 step: BounceE ≥ 10 steps per trip, BounceP ≥ 22, every event gadget ≥ 1.

A traversal from one right end to the next is a finite chain of rules: - every P-mode rule strictly decreases the left material L = P + Σ (p_i + q_i) (BounceP, Eat*P: P drops; Push1/Push1End/Absorb: walls are removed and P becomes p − 1 or p_J), or ends the traversal; - every edge-mode rule strictly decreases the right material d + Σ chunk sizes (merging is a tape identity), or ends at a right end; - edge mode never returns to P-mode before the next right end.

So (mode, L, right material) decreases lexicographically, and P-mode comes first.

Halting needs B> 0 0 1 (check A3). D is entered only by C0 and F0. - F is entered only by C1, which writes the 0 that F0 then sends D onto. - C0 returns D onto the 0 that A1 just wrote. - The only other entry to C is B0.

So every halt is B0, C0, D1: B reads 0, C reads the next 0, and D reads the following 1.

Every rule of §3-§4 is an exact run, so a rule never reads B> 001. In the grammar the pattern comes up only when the right sweep enters a chunk on the odd alignment, that is, when it eats an odd (10)-run that is not at the tape end (I1: 30/30 such frames halt). H1 (inner a even) and §5.4 keep every chunk's (10)-runs even: - Push1 builds them from inner a's and ak + 2. That these runs are even needs "ak is even whenever Push1 fires at a wall". This is a census fact (parity census, 0 exceptions to 1e12 steps), not derived, and not a local parity fact: eats with an odd six-block count flip ak (75 of 163 eats from blank). It is part of G5. - EatLast handles the one odd last run that sits at the tape end.

So "no halt" reduces to: the orbit stays inside the ruled domain (every step is a rule of §4) — which is exactly the closure of the invariant. Without the closure (G1, G2), the halting argument is incomplete. The window family (§4.4) already leaves the ruled domain, so the rule set itself has to grow before an invariant can close.
