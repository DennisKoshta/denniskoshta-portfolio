1RB0LD_1RC0RE_1LD0RE_1LA0LA_1RB1RF_1RB---: never halts

This machine never halts. It is a binary counter: each time the head returns to the left edge of the tape, the tape spells out the counter's digits. From there the machine either adds 1 to the counter (a carry) or re-pairs the halves of every digit (an overflow).

Its transition table is the table of another machine, called the parent below, with four of its six states renamed. No symbol and no direction changes. So every window lemma, rule and step formula of the parent's proof carries over word for word, and so does the whole invariant argument.

Only the start differs. This machine starts in the state that corresponds to the parent's state D, so from the blank tape it follows a different orbit of the same macro map. The proof is a 687-step initial segment, a check that the parent's invariant holds where that segment ends, and the parent's induction.

Summary

This is the parent's binary counter, with head state D where the parent has C. There are two kinds of macro step:

  • a carry M adds 1 to the counter;
  • an overflow O re-pairs the halves of every digit.

The three-class invariant INV = Common ∧ (A ∨ B ∨ C) of P§3 is closed under M and O.

What carries over

σ is a pure renaming of states (Lemma R, §0). So every window lemma, rule, step formula and the whole invariant argument carry over word for word.

The invariant is not adjusted.

What changes

Only the start differs, because this machine starts in what is the parent's state D. From the blank tape it follows a different orbit of the same macro map, and reaches the INV state below:

this machine:   K((1,1,9); 8, 1)   (class A)   at step 687
the parent:     K((1,1,3); 4, 1)               at step 215

The proof is that 687-step initial segment, a base-case check, and the parent's induction.

Relabelling

For a configuration c, let σc be c with its head state renamed by σ. The tape and the head position stay the same.

Lemma R (relabelling).

c → c′ under the parent     if and only if     σc → σc′ under this machine
c is halted                 exactly when       σc is halted

The second line holds because F1 is the only undefined cell, and σ fixes F. So every run c →ⁿ c′ of the parent gives a run σc →ⁿ σc′ here, of the same length, and conversely.

Proof. If the parent has δ(s, x) = (y, d, t), this machine has δ(σs, x) = (y, d, σt), by the table above. ∎

Start

This machine's c0 is

c0 = 0^inf A> 0^inf = σ(0^inf D> 0^inf)

So its run is σ of the parent's table run from 0^inf D> 0^inf. This is not the parent's own run, which starts in A.

Halting cell

Only E1 = 1RF enters F, and F1 is ---, exactly as in the parent (σ fixes E and F). So the machine halts exactly when E reads 1 with a 1 to its right.

3. The argument (complete)

Theorem. 1RB0LD_1RC0RE_1LD0RE_1LA0LA_1RB1RF_1RB--- does not halt from the blank tape.

  1. Initial segment. The machine runs from c0 to K((1,1,9); 8, 1) in exactly 687 steps without halting. This is a finite exact computation (§2); in Rocq it is init, proved by solve_init.

  2. Base. INV([(1,1,9)], 8, 1) holds, in class A (§2).

  3. Transfer. P§3.2 (coverage) and P§3.3 (closure): every INV state has a macro step M or O, of at least 32 machine steps, to an INV state. - These statements are about the triples and a, b, and the macro steps are rule instances K → K′ of the parent. - By Lemma R, each such instance is a run σK →⁺ σK′ of this machine of the same length, and σK is the K of §1. - So coverage and closure hold verbatim for this machine's K-configurations.

  4. Conclusion. By induction from the base, the run is an infinite chain of macro steps, each of at least one machine step, so it never halts (progress_nonhalt_cond with P := INV, as in P§5). - No macro step reaches the halting cell: each is an exact computation from one K to the next, composed of window lemmas in which F reads only 0. ∎

The parent's invariant argument (P§3) never refers to the parent's own orbit, so it applies to this orbit unchanged.

Coupling with 1RB0LE_1RC0RC_1LD0RB_1LA0LE_1LD1LF_1LD---

In the shared triple notation, compare this machine's macro orbit with that machine's, which starts from its first INV state K((1,1,2); 8, 5) at step 483 (P§0). The two reach a fixed offset after 54 macro steps (step 25,718 here, 25,618 there).

Observed facts, checked on the two abstract macro orbits for 1,199,946 further macro steps (to t ≈ 3.7·10¹² machine steps, 93 overflows):

  • from then on, at every macro step, the two states are equal except for one exponent near the top, larger by 3 here: v_1 in class A, u_2 in class B (where the top is (0,0,1)), u_1 in class C;
  • the same rule fires at every macro step.

Where the +3 travels

  • O sends the top's v_1 to digit 2's u (class A → B, new top (0,0,1)).
  • The top fall merges digit 2's u into the new top's u (B → C).
  • The next O sends u_1 to the new top's v (C → A).

6. Numerical checks

These simulation checks are independent of the .v; the result rests on the .v alone.

  • Lockstep: from the blank tape, this machine and σ of the parent's table run from 0^inf D> 0^inf agree at every step to 2·10⁷ (state, symbol written, move), with identical tapes at the end.
  • Window lemmas: each of the 20 lemmas of §1 runs exactly as stated on this table, never reading outside its window, with σ of the parent's transitions.
  • F is entered only in T4, T9 and T13, and reads 0 each time.
  • Rules: M on 700 random K-configurations (k = 0..6; 273 with a drop, 257 with u* = 0; a, b ≥ 0) and O on 350 (m = 1..7) give exactly the stated result and step count.
