Summary. This is the parent's binary counter, with head state D where the parent has C. At each return to the left edge the tape is K = 0^inf <D (01)^b 000 (01)^a d~_m .. d~_1 1001 0^inf. A carry M adds 1 to the counter, an overflow O re-pairs the halves of every digit, and the three-class invariant INV = Common ∧ (A ∨ B ∨ C) of P§3 is closed under M and O. σ is a pure renaming of states (Lemma R, §0). So every window lemma, rule, step formula and the whole invariant argument carry over word for word. The invariant is not adjusted. Lemma R (relabelling). For a configuration c, let σc be c with its head state renamed by σ; the tape and head position stay the same. Then c → c′ under the parent if and only if σc → σc′ under this machine, and c is halted exactly when σc is (F1 is the only undefined cell, and σ fixes F). So every run c →ⁿ c′ of the parent gives a run σc →ⁿ σc′ here, of the same length, and conversely.

Proof. If the parent has δ(s, x) = (y, d, t), this machine has δ(σs, x) = (y, d, σt) by the table above. ∎

Start. This machine's c0 is 0^inf A> 0^inf = σ(0^inf D> 0^inf). So its run is σ of the parent's table run from 0^inf D> 0^inf. This is not the parent's own run, which starts in A.

Halting cell. Only E1 = 1RF enters F, and F1 is ---, exactly as in the parent (σ fixes E and F). So the machine halts exactly when E reads 1 with a 1 to its right.

3. The argument (complete)

Theorem. 1RB0LD_1RC0RE_1LD0RE_1LA0LA_1RB1RF_1RB--- does not halt from the blank tape.

  1. Initial segment. The machine runs from c0 to K((1,1,9); 8, 1) in exactly 687 steps without halting. This is a finite exact computation (§2); in Rocq it is init, proved by solve_init.
  2. Base. INV([(1,1,9)], 8, 1) holds, in class A (§2).
  3. Transfer. P§3.2 (coverage) and P§3.3 (closure): every INV state has a macro step M or O, of at least 32 machine steps, to an INV state. These statements are about the triples and a, b, and the macro steps are rule instances K → K′ of the parent. By Lemma R, each such instance is a run σK →⁺ σK′ of this machine of the same length, and σK is the K of §1. So coverage and closure hold verbatim for this machine's K-configurations.
  4. Conclusion. By induction from the base, the run is an infinite chain of macro steps, each of at least one machine step, so it never halts (progress_nonhalt_cond with P := INV, as in P§5). No macro step reaches the halting cell: each is an exact computation from one K to the next, composed of window lemmas in which F reads only 0. ∎

The parent's invariant argument (P§3) never refers to the parent's own orbit, so it applies to this orbit unchanged.

4. How this orbit relates to its siblings (remark, not used in the proof)

Coupling with 1RB0LE_1RC0RC_1LD0RB_1LA0LE_1LD1LF_1LD---. In the shared triple notation, this machine's macro orbit and that machine's (from its first INV state K((1,1,2); 8, 5) at step 483, P§0) reach a fixed offset after 54 macro steps (step 25,718 here, 25,618 there). Observed facts, checked on the two abstract macro orbits for 1,199,946 further macro steps (to t ≈ 3.7·10¹² machine steps, 93 overflows): - from then on, at every macro step, the two states are equal except for one exponent, larger by 3 here, on the top digit: v_1 in class A, u_2 in class B (where the top is (0,0,1)), u_1 in class C; - the same rule fires at every macro step.

Where the +3 travels: O sends the top's v_1 to digit 2's u (class A → B, new top (0,0,1)), the top fall merges digit 2's u into the new top's u (B → C), and the next O sends u_1 to the new top's v (C → A). This explains the tapes at 10⁹ steps: 77,691 cells and 38,839 nonzero here, against 77,685 and 38,836 for that machine. The 6 extra cells are the three extra 10/01 blocks.

The parent's own run is a different orbit, with no such coupling (76,245 cells and 38,119 nonzero at 10⁹ steps).
