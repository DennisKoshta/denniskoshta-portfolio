Candidate rules (macro model, scripts/macro.py)

E-event K(L; a; r; R) := 0^inf 1^b1 0 ... 0 1^bp 0 1^a E> 0^r R 0^inf, with E reading the first 0 of 0^r. L = closed blocks b1..bp, a = the block next to the head, r = the zero run (inf when the run reaches the blank), and R = the pair-form tokens P^j = (10)^j, Z^n = 0^n, D = a lone 1 that is followed by a pair. In each rule, y and b are the last two closed blocks, and a missing block counts as 0 (left edge).

Halting. E1 is the only undefined transition, and E is entered only by D0. Going through the rules, E can read a 1 only in H: a right pass that meets exactly 0^2 after a pair. So the machine halts iff some C-pass meets Z^2.

Parity. At all 1,722,791 E-events to 5e7 (scripts/ctx.py), and at all 103,296 to 3e6 (scripts/inv.py --real): - every closed block is even; - r is odd or inf; - every zero run Z in R is odd (1, 3, 5, ...); - D always sits between two pair groups. Each rule keeps these parities (b+1, x+1, n-2, r-2 are odd when b, x are even and n, r are odd). This holds only while three side conditions hold: - (I2) a = 2 only with r = inf; - (I6) a pair group just before a zero run has j >= 2; - (I7) the group after a D has j >= 2 unless it is the last token. The danger is drop_pair on a P1 before a Z, which merges a Z into r and makes it even.

Open. The side conditions hold on the real run, but they are not inductive. In the random closure test (scripts/inv.py), about 2% of steps from INV states leave INV, all through r = 1 events (D creation). The natural strengthening (r = 1 implies the next group has j >= 3) already fails on the real run at step 2,403,364. So the non-halting argument needs a finer context invariant, possibly a regular language over abstract tokens.

Template comparison

CounterClass2v1..v4 (upstream verify/, BB6 HEAD) all differ from this table in exactly one slot, our A0 (v1: 1LC in our names, v2-v4: 0LB; v4 also has E0 = 1LD). They start in our D (v1, v4), E (v2) or C (v3). - A0 is the turn that starts rule Ee. In the templates, A turns left there and continues; here A0 = 1RB makes B erase the next two closed blocks. - v1's rule set is a deterministic counter on a fixed skeleton: SkelE n = 1^2 (0 1^(6+4k) 0 1^(6+4k))_k, with Bnext on (n, j, b), ClosedCall side lemmas and GoodB. Ours has no fixed skeleton: the block list is a stack that rules Ee/C2/C4 push and pop, with chaotic contents. - So the template applies only in its top-level shape (progress_nonhalt_cond with an invariant on a symbolic config type). The Eqv_v3 TM540 / Eqv_v2 TM359 equivalences link this machine to two other unproved tables, so they give no proof either.

Cryptid check (ground rule 6)

Not cryptid-like in the sense of rule 6: there is no pseudo-random arithmetic. The macro rules only add and subtract (y+3, b+1, x+2, n-2), and halting needs a parity defect (an even zero run) that every rule avoids while the local context conditions hold. The unpredictability is combinatorial (a shuffled two-stack list), as in the chaotic classes, so the realistic proof is an invariant (closed language), not a counter formula.

Funded stage (2026-10-10, inv_search)

Funded 2026-10-11 (Dennis: go with recommendations). Goal: an inductive invariant over the validated macro model, or a precise obstruction, then park. Result: no invariant; a precise obstruction for every left/right-product n-gram invariant with short left windows, plus evidence that the missing invariant is not local. Parked (STUCK). Covers 469 (start A) and 599 (start D): every run below uses both starts.

What was built (all stdlib, in scripts/; outputs in scripts/absint_runs/): - absint2.py: n-gram CPS at the macro level. Abstract state = head (a, r or the C-pass x) + the first K symbols of each stack (closed blocks; tokens P/Z/D). Integers are exact below T, else n mod M, with separate (T, M) for head values, pair counts, zero runs and blocks. Every rule of macro.step / macro.cpass is replayed on all abstract branches; the worklist re-wakes states when a new (K+1)-gram appears. - absint3.py: the same with R read as groups (j, separator), so one window slot holds about two tokens. - absint4.py: absint3 plus one parity bit per stack for the part beyond the window (weights of GP below). Revealing the bottom marker needs bit 0, so a spliced tail must keep GP. This is a sound refinement. - splice.py: the obstruction test. Take two sampled E-events of the real run that share a window of W consecutive entries (exact values, or matched under an abstraction). Keep the first's head, the first's top p+W entries (1 <= p <= 2) and the second's rest. The spliced configuration has the first's head and first window, and every (W+1)-window in it occurs in a reachable configuration. So every product n-gram invariant with windows of at most W entries contains it, whatever the value abstraction and whatever the other stack does. Then run the macro model up to 10,000 macro steps. verify_splice.py re-runs every halting splice on the TM itself (C engine, from the constructed tape). - gpar.py: the global parity GP (below), checked on the real run, rule by rule, and on the splices.
