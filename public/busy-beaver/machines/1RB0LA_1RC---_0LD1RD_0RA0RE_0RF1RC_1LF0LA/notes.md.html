Halting transition

The only halt is B reading 1. B is entered only from A0 (1RB), and A0 follows D0 (0RA) when it matters. So the halt pattern is a right-moving sweep where D reads 0, A reads the next 0 and the cell after that is 1:

C> 1 0 0 1      or      0 C> 0 1

Counting phase (exact)

At every C right record (head moving right into fresh tape in state C):

0^inf L 1^N 0^2  s_1 0 s_2 0 ... s_2w 0  1 C> 0^inf        s_i in {1^2, 1^3}

Read the s_i in pairs, MSB first, as base-4 digits:

pair digit
23 0
22 1
33 2
32 3
4 3 0, with a carry pending into the pair on its left

R1. From one C right record to the next, the value goes V -> V+1. - Checked on 10,416 of 10,416 record transitions: random values, widths w = 2..40, top digit 3, 24 records each (scripts/validate_increment.py). - No halt occurred in any of them. - Leading pair 23 (digit 0) is not stable; every real counter has top digit 3, so a w-pair counter makes at most 4^(w-1) increments before overflow.

Per tick the head crosses the whole counter: a left zigzag sweep (A/C/D/F turns, net -3 or -4 cells per zigzag) turns the pairs into blocks 1^(3k), then a right sweep (A0 1RB, B0 1RC, C/D/E over 1s) turns them back, and the trail gains cells.

Measured at w = 23 (steps 1.0e8 to 1.2e8, 39,847 increments): - about 502 steps per increment; - trail growth 79,689 cells, so about 2 per increment (not exact: depends on carries; R3 is a measurement only).

Phase 1 (from blank) is an 8-pair counter that overflowed at step 3.73e6 (trail about 40,124).

Phase events (where halting can happen)

  • Overflow. All digits 3 plus a carry. A sweeps left erasing the trail (A1 = 0LA). Each separator 0 1^2 0 inside it becomes a single-1 marker.
  • Rebuild. A small counter is rebuilt at the left end and counts through the gap. Sub-counters overflow in turn, leaving marker gaps 0^(2*4^k - 2) (seen at 1.36e7: 0^8190, 0^2046, 0^510, 0^126, 0^30).
  • Collision. The counter front reaches a marker or the old counter's remnant. It absorbs it (the word grows) or the machine halts.

Cryptid check (stop rule)

The counting rule itself is clean arithmetic: R1 is exact. But the halting question reduces to exact coincidences at phase events, between counter values and gap lengths built from irregular big numbers. No invariant rules them out, and there is no margin to watch: the outcome is all-or-nothing per event. That is a cryptid-like lottery, so the stop rule applies.

What would settle the next event is an exact phase-level model: - R1 in closed form, plus exact trail growth and step cost per increment; - the overflow, erase, nested rebuild and collision steps simulated on a run-length tape.

It decides the event at about 4.6e15 steps: a HALT (checked-runner route as for C2-552/W5-5, which needs a formal base-4 increment lemma) or the next phase's parameters. That is next_goal, funded only by a new decision.
