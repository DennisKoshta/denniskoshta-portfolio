Summary. This is the parent's binary counter, with head state A where the parent has B. At each return to the right edge the tape is K = 0^inf 10 01 d_1 .. d_m (10)^a 000 (10)^b A> 0^inf, with digits (10)^u 00 (01)^v (bit 0) and (10)^u (01)^v (bit 1). A carry M adds 1 to the counter, an overflow O re-pairs the halves of every digit, and the three-class invariant INV = Common ∧ (A ∨ B ∨ C) of P§3 is closed under M and O. τ is a pure renaming of states (Lemma R, §0), so every window lemma, rule, step formula and the whole invariant argument carry over word for word. The invariant is not adjusted. Only the start differs, because this machine starts in what is the parent's state B: from the blank tape it follows a different orbit of the same macro map and reaches the INV state K((1,1,10); 8, 1) (class A) at step 732, where the parent reaches K((1,1,2); 8, 5) at step 483. The proof is that 732-step initial segment, a base-case check, and the parent's induction.

τ: A↦E, B↦A, C↦B, D↦C, E↦D, F↦F (a 5-cycle on A–E). Row τ(s) of this table is the parent's row s with every target state t replaced by τ(t); symbols and directions are unchanged. For example, the parent's C1 = 0RB becomes 0Rτ(B) = 0RA, which is this machine's B1. Among all 720 state renamings, each with and without mirroring, τ without mirror is the only map from the parent's table to this one.

Lemma R (relabelling). For a configuration c, let τc be c with its head state renamed by τ; the tape and head position stay the same. Then c → c′ under the parent if and only if τc → τc′ under this machine, and c is halted exactly when τc is (F1 is the only undefined cell, and τ fixes F). So every run c →ⁿ c′ of the parent gives a run τc →ⁿ τc′ here, of the same length, and conversely.

Proof. If the parent has δ(s, x) = (y, d, t), this machine has δ(τs, x) = (y, d, τt) by the table above. ∎

Start. This machine's c0 is 0^inf A> 0^inf = τ(0^inf B> 0^inf). So its run is τ of the parent's table run from 0^inf B> 0^inf. This is not the parent's own run, which starts in A.

Halting cell. Only D1 = 1LF enters F (it is τ of the parent's E1), and F1 is ---. So the machine halts exactly when D reads 1 with a 1 to its left.

3. The argument (complete)

Theorem. 1RB0RB_1LC0RA_1LE0LD_1LC1LF_1RA0LD_1LC--- does not halt from the blank tape.

  1. Initial segment. The machine runs from c0 to K((1,1,10); 8, 1) in exactly 732 steps without halting. This is a finite exact computation (§2); in Rocq it is init, proved by solve_init.
  2. Base. INV([(1,1,10)], 8, 1) holds, in class A (§2).
  3. Transfer. P§3.2 (coverage) and P§3.3 (closure): every INV state has a macro step M or O, of at least 32 machine steps, to an INV state. These statements are about the triples and a, b, and the macro steps are rule instances K → K′ of the parent. By Lemma R, each such instance is a run τK →⁺ τK′ of this machine of the same length, and τK is the K of §1. So coverage and closure hold verbatim for this machine's K-configurations.
  4. Conclusion. By induction from the base, the run is an infinite chain of macro steps, each of at least one machine step, so it never halts (progress_nonhalt_cond with P := INV, as in P§5). No macro step reaches the halting cell: each is an exact computation from one K to the next, composed of window lemmas in which F reads only 0. ∎

The parent's invariant argument (P§3) never refers to the parent's own orbit, so it applies to this orbit unchanged. The parent's orbit statistics (P§7) are evidence there, not premises.

4. How this orbit relates to its siblings (remark, not used in the proof)

In the shared triple notation, three of the four starts of this table run orbits of the same macro map that lock together: - With the mirrored C-start 1RB0LD_1RC0RE_1LD0RE_1LA0LA_1RB1RF_1RB--- (base K((1,1,9); 8, 1) at step 687): from macro step 0 on, the two states are equal except for one exponent, larger by 1 here, on the top digit, and the same rule fires at every macro step. - With the parent (base K((1,1,2); 8, 5) at step 483): from macro step 54 on (step 25,851 here, 25,618 in the parent), the states are equal except for one top-digit exponent, larger by 4 here, with the same rule at every macro step. - Where the extra exponent sits: v_1 in class A, u_2 in class B (where the top is (0,0,1)), u_1 in class C. His rules and hypotheses. - Block, stride and collision rules, the cycle, and the exponent table without collisions: true. His 14 rules alone, from L0 b> X^2 R at step 24, reproduce the run to step 10⁹; they miss only C0 C0 < (a halt) and C C0 <. - Collisions only in pass 4: true. INV gives passes 1–2 (class A has no drops) but allows drops in class B. There the top falls by L3 C0 < and the LSB never drops; every other digit j starts with v equal to the u_j of the overflow from class A, which is ubar_j ≥ 2^(j−1) + 1 (F3, F1), and the digit is touched at most 2^(j−1) − 1 times before the top falls, so it never runs out. A collision removes one digit, i.e. two exponents. - First group never 0: true at cycle starts, where u_j − 1 ≥ 2^j − 1 and a ≥ 2^(m+1) − 1 (class C at all bits 1). Mid-cycle the j-th one falls by 2^j, to v_j − 2 at the overflow from class A; there INV proves only the weaker bound ≥ −1 (vbar_j ≥ 1). - Second group even: true for each v_j − 2 (v_j + 1 is odd); the X^n R exponent b + 2 is odd at every left-end visit (b odd), as he guessed.

C C0 at the right end: no. C C0 < is D reading the last 1 of a 1001 with a nonzero cell further left. It does not occur in the first 732 steps; after them D reads 1 only in T4, T9 (L0 <) and T13 (X C0 <), and T4 meets a 1001 only where Lb starts on a digit (u,1,1). So C C0 < is Lb on a bit-1 digit with v = 1 (his <D 0111). The right end is the LSB digit and the block (10)^a 000 (10)^b; the block holds no digit, and INV excludes the LSB. A carry sweeps only digits with v ≥ R + 1 ≥ 3 (class A, F0) or v even (B, C); an overflow from class C has all v even; an overflow from class A has v_m = vbar_m, which is ≥ 1 and even, so v_m ≥ 2: class A starts at the base (vbar = 10) or after an overflow from class C, where F3 gives the new LSB vbar = a − 2^(m+1) + 2 with a even (a + R_tot even, R_tot = 0), and class A keeps it. INV leaves open only a digit (u,1,1) above the LSB at an overflow from class A, which needs u_j = 2^j at the overflow from class C before it (v_j = u_j − 2^j + 1).
