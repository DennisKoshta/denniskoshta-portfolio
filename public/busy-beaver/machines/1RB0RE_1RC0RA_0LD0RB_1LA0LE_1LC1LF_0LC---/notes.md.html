Configuration family

Round start (the head has just turned right at the counter boundary):

K(w, b, c) = 0^inf w 0 E> 101 (001)^b 0001 (001)^c 0^inf
  • w is the counter: 3-cell digits, most significant first. A clean digit is x0y with value e = 2x - y: 001 = -1, 000 = 0, 101 = 1, 100 = 2. Blank = 0, so leading zeros are free.
  • Counter value C(w) = sum e_i 4^i. Every integer has exactly one such representation (base 4, digits -1..2).
  • Read as cells from the boundary leftwards, the bits have weights -1, (0), +2, -4, (0), +8, ...: a negabinary number with every third cell kept at 0.
  • Right of the boundary is the bell: 101 (the 1-gap), b blocks 001, the 3-gap defect 0001, then c blocks 001. L = b + c + 1 is the bell length in blocks.
  • Real run: 243,388 round starts to 1e9 steps (scripts/eats.c, work/rounds_1e9.txt). The right side has this exact form at every one of them (c = 1 once, early). The counter uses only the codes 001/000/101/100 plus the dirty 010/011.

Rules

  • ROUND (b >= 3, clean w): K(w,b,c) -> K(w+1, b-1, c+1) in 12b + 22 + 14t (+4) steps. Here t is the number of trailing 100 digits, and the +4 applies when the digit that absorbs the carry is 000 or blank.
  • The head zigzags right (9 steps per block) carrying a defect to the 3-gap, which moves one block left. Then a straight left sweep comes back and adds 1 to the counter.
  • c plays no part.
  • Validated 300/300 random instances (k <= 6 digits, b 3..40, c 0..40; scripts/validate_round.py seed 11, work/validate_round_seed11.json). The step formula fitted 40/40.
  • ROUND, dirty w: the shape is the same (b-1, c+1), but the counter map is not additive.
  • Example: 010 -> 100 001; 001 010 -> 101 001; 100 010 -> 100 001 001.
  • Exhaustive over every 1-3 digit word on the 6 codes with a dirty digit, 40-70 rounds each (scripts/inc_closure.py): 172/172, no halt, no other code ever appears, and every word is clean again after the carry passes through.
  • EAT (b = 2): the next round reaches the counter itself.
  • 1-7 sub-rounds follow (most: 1-2), each a full trip over the bell, until a round start with b' >= 3.
  • Measured (random, scripts/eat_random.py, 3,000 instances clean + 30%-dirty, c 20..120): never halts, always returns to K-form with b' = c + delta, delta in 1..5, c' in 0..6.
  • Real run to 1e9 (496 eats): the boundary moves left by d = 3j+2 cells (d = 2: 228, 5: 137, 8: 68, 11: 27, 14: 20, 17: 6, 20: 6; d = 0 four times, early). Bites of 5 or more cells leave every cell left of the new boundary unchanged (pure truncation of the low end). Bites of 2 cells rewrite 1-8 cells near the boundary (a carry or borrow).
  • Since d = 2 (mod 3), every eat shifts the digit alignment by 2 cells. The surviving high cells are then re-read in the new alignment, which is where the dirty digits 010/011 come from (5.8% of round starts to 1e9).
  • No closed form for w' yet. This is the open part.
  • Halting routes (direct simulation from constructed K):
  • A: a round on w ending in cells 1 110 (low block 110 with a 1 to its left) halts in 6 steps. All four 2-digit cases.
  • B: an eat on a counter with top block 111 can halt (111001011, 111000001, 111000101, at c = 30, 31, 32).
  • Feeding B: an eat on a top-011 counter that bites down to it leaves a 110/111 top (14 words of 3 digits, scripts/eat_closure.py, work/eat_closure_k3.txt, work/closure2_k3.txt). Such tops are harmless under rounds (they become clean high digits after 1-8 rounds), but another eat on them first can halt.

Long run

  • tools/sim.py: no halt to 1e10 steps (span -5352..1095).
  • scripts/eats.c (direct C, eats only): no halt to 3e10 steps. That is 1,597 eats, L = 3,072 blocks at the end, and a counter of 6-8 digits.
  • A cycle (L rounds) costs about 12 L^2 steps, so L grows like step^(1/3), about 1-3 blocks per eat. The counter stays at about log4(L) + 2 digits: each cycle adds about L to it, then the next eat bites its low end.
  • Pre-eat counters (the K(w,2,c) states, work/eats_3e10.txt): over all 1,597 there are only 8 dirty blocks, all 010, 7 of them the top block. The top block is never 011 or 111, so halting route B is never even set up.

Template comparison (W4-2 / BECv5)

  • Same architecture as W4-2 (BECv5 TM1/TM2 plus an invariant). W4-2's K(w,n,m) = w <A 1 (10)^(1+n) 0 (10)^m, with:
  • a bounce n-1, m+1, w -> phi(w) (binary +1);
  • an overflow at n = 0 that bites q+1 cells;
  • parity of q deciding safety;
  • dirty words after the bite.
  • Here the bounce is the ROUND rule with a signed base-4 counter on 3-cell digits.
  • The overflow is a multi-sub-round EAT that bites 3j+2 cells, and the bite re-aligns the digits.
  • The halting points are dirty top digits under a deep bite, rather than W4-2's q-odd landings.
  • RIncs/LIncs-style lemmas carry over in shape (ROUND = RIncs + a left sweep). The eat and the dirty-digit bookkeeping are new.
  • The table is not a near neighbour of any BECv5 machine (different transitions throughout).

Cryptid check (ground rule 6)

  • The abstract system has halting branches (A, B), so non-halting rests on avoiding states, as in W4-2.
  • Avoidance looks structural, not lucky:
  • Halting needs a 011/111 top at an eat. That top is a dirty high digit that survived a whole cycle of about L >= 4^5 increments without a carry cleaning it, and then met a bite deep enough to reach it.
  • In 1,597 eats the precondition never occurred once, not even as a near miss: the pre-eat counters hold 8 dirty blocks in all (010) and never a 011/111 top.
  • A random-digit model would predict many hits: in the exhaustive 3-digit eat test, 51 of 777 cases (6.6%) leave a 110/111 top, and in the wider closure test 60 of 1,152 cases fail, some halting outright.
  • Verdict: not cryptid-like on current evidence. The eat rule still has to be written exactly before an invariant can be stated.

What the observe stage missed

  • Dirty digits are not values. An eat realigns the counter into 0my digits (000, 001, 010, 011). A carry into a 010 run converts the whole run at once and sends a large carry upward. Each realigned word has a well-defined effective value G (value after conversion minus increments, constant once converted). G(010^k) = 6, 42, 426, 2730, ..., about (4k - 16/3) 4^k.
  • Excursions. The counter inflates through such conversions and grows long runs of 001 digits. Up to 121 digits more than log4(c) appear in the long run; 16 digits already at 1.5e10 in the direct run. Each excursion is then eaten back (img/excess_all.png).
  • Dirty K0 words do occur after 3e10: 976 of 611,577 cycles (2nd digit 010, top 011, top 110, ...; work/abstract_dirty_k0.txt). Post-eat 111 tops: 37 in 1e5 cycles, always carried within the cycle (margin R / t >= 7.1; work/post_eat_111_1e5.txt).

How the second model works

The rules below were derived from traces of constructed tapes, not taken from the stage-1 notes.

  • Round = COUNTER + BELL. From w 0 E> 1..., the head goes left into the counter. It first comes back to the boundary cell in state C, with the cell left of the boundary now 1. In between it visits no bell cell except the boundary cell, which E rewrites as 1. So w' = COUNTER(w) depends on w alone, and it is computed by running the TM on the counter cells.
  • BELL lemma (b >= 1). From 1 C> 101 (001)^b 0001 (001)^c, the head first returns left of the boundary in state A reading 1, after 12b + 17 steps. The bell is then 101 (001)^(b-1) 0001 (001)^(c+1). The rightmost cell visited is 3b + 5, inside the defect, so c plays no part. Then A1 = 0RE closes the round, so a round costs COUNTER + 12b + 18.
  • Clean increments (the carry stays in clean digits): +1 in base 4 with digits -1..2, at a cost of 4 + 14t + 4[the absorbing digit is 000 or blank]. These are batched in closed form, up to the point where the clean low part would carry into the lowest dirty digit (m = 1). Step sums come from residue counts: the v with t(v) >= k are the v congruent to 2(4^k - 1)/3 mod 4^k.
  • Carries into a dirty digit are run as one exact TM COUNTER run on the whole word. There were 2,096,688 of these and 2,234,206 arithmetic batches.
  • The eat uses no rule at all. The TM is run exactly, at the true c, by a macro simulator on run-length blocks.
  • Its only shortcut is a shift rule a P^j -> P' a P^(j-1) (and its mirror image), found by simulating the rule's window and checked there; the head never leaves the window.
  • A period in which E reads a 1 is refused, so no K-form can hide inside an accelerated stretch.
  • The eat ends at the first K-form, detected cell by cell.
  • So the eat does not assume c-independence. There were 4,264,432 rule applications over all eats, and the eat at c = 1.2M takes about 0.3 ms.
  • Run from blank to the halt: 503 s in Python (run.py; output k0_model_all.txt, one line per cycle start).
