Invariants: why a long run is not a proof

The answer

A long run without a halt proves nothing. Three of our machines ran a billion steps without halting, and all three halt later. A proof needs an invariant: a fence around a set of tapes that the run gets into, that no rule can carry a tape out of (the fence is closed), and that holds no halting tape.

1A billion steps tells you nothing

Simulating is only this: one table lookup per step. No finite stretch of steps can tell you that the next one is not the halt. You need an argument that covers every step at once.

2An invariant is a fence the rules cannot cross

Module 4's W5-3 moves from one eat configuration E(p,N) to the next. Five proved rules, M1 to M5, say where E(p,N) goes next. They cover almost every (p,N), and beat 3 shows the gaps. So the whole run is a walk of points (p,N).

Each dot is an eat configuration of the real run, up to step 3,000,000. From E(2,4) at step 165 on, all 62 lie on or under the line N = 2p. That region is the fence J: 1 ≤ N ≤ 2p. Tap any point in it: the page applies the rule, draws the arrow, and runs the real machine from that tape to check. The arrow lands inside again, every time. That is what closed means.

Check closure for every point, not just the ones you tap

Now the proof is three lines. The run is inside J at step 165 (its first eat configuration, E(0,1) at step 31, is just outside, so the proof replays those 165 steps exactly). J is closed. And none of the five rules ever uses F0, the machine's only undefined transition. So the run never leaves J, and never halts.

Why the deciders miss fences like this: the automatic deciders describe tapes with a fixed pattern-matcher, which can count a block only up to a fixed size or modulo a fixed number. J compares two numbers that both keep growing, so they cannot express it. (Module 1: what the deciders catch)

3Failure 1: a fence too wide to close

Try a simpler fence: drop "N ≤ 2p" and keep only N ≥ 1 (the hatched area). Now E(0,62) is inside, and no rule covers it. Its N is rule M5's case: N + 2 = 64 = 23+3, so t = 3.

M5 walks a defect left through the 10 pairs, two pairs per walk, 2t−1 − 1 times, so it needs enough pairs on the left: p + 7 ≥ 2t. From E(0,62) that is three walks, and the third finds only 1 of the 2 pairs it needs. Each red cross is such a point, and one point with no rule is enough: closure cannot be shown.

The machine itself does not care. From E(0,62) it reaches E(12,7) at step 688, back under the line, and every red cross does the same at its next eat (tap one). A fence only has to be one you can prove closed. It may leave out tapes that never halt.

4Failure 2: the shape alone is not enough

So a fence that only says which pieces a tape has, in which order, contains tape B, and B halts. No such fence can be closed. What keeps the real run safe is a balance of sizes, between its counter value and its widths, and we found no size fence that closes. W4-7 is parked.

5Success: #11's fuel invariant

#11 is a binary counter whose digits carry fuel (module 3, beat 3): v is the number of 01s in a digit. R is the number of carries still coming to that digit before the next overflow. Between overflows, each carry takes one 01 from v and one from R, so the spare fuel v − R never shrinks.

The rules break only if a carry reaches a 0-digit with no 01 left. Phase A of the invariant rules that out by asking every digit for spare fuel: v ≥ R + 1. Steps 283 and 383 fail it, because their low digit has v = R.

Step 142 fails on the end block, the 10s right of the digits. Its counter is all 1s, so an overflow comes next, and the end block becomes the fuel of a new low digit. S is the spare that digit will get: here S = 0, which is the low digit with v = R at step 283.

Phases B and C cover the cycles in which the top digit runs out and falls (at step 752 its v = 1 is used by the next carry, and it merges into the digit below). There the invariant uses parity instead: every 1-digit has an even number of 01s, so a carry that turns it into a 0-digit leaves it at least one. From step 483 on every row is inside, so the proof replays the first 483 steps exactly and the invariant takes over from there.

Recap
  1. A long run is evidence of nothing: C2-552 ran 109 steps without halting, and it halts, at about 1.765·1044 steps.
  2. An invariant is a fence: the run gets in, every rule keeps it in (closed), and nothing inside halts. W5-3's J: 1 ≤ N ≤ 2p is one, and so is the wider 1 ≤ N ≤ 3p.
  3. A fence fails when a point inside has no rule (E(0,62) with N ≤ 2p dropped), or when it sees only the pieces of a tape, not their sizes (W4-7's tape B).
  4. #11's fence is about fuel: every digit keeps spare fuel for the carries still coming to it.
